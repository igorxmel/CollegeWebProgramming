# Практическая работа №11. Работа с Fetch API

Страница, которая получает данные из открытого API методом `fetch()` и выводит их
карточками. Данные из Rick and Morty API, как просит методичка, а оформление карточек
взято из проекта «Dream Sneakers»: те же цвета, шрифты и скругления, что в лендинге из
первой работы.

## Описание решения

```
Solution/
    index.html    разметка: заголовок и контейнер для карточек
    script.js     запрос, обработка ошибок, создание карточек
    styles.css    оформление и сетка
```

Серверной части нет, это обычная страница, и все запросы идут прямо из браузера к
`https://rickandmortyapi.com/api/character`.

Методичка называет Rick and Morty основным вариантом и разрешает взять другой API, в том
числе по теме собственного проекта. Я оставил основной: в нём есть всё, что требуют
шаги (результаты, вложенные объекты `origin` и `location`, массив эпизодов, дата). А
дизайн, как там и сказано, адаптирован под проект. Акцентный цвет `#ec1c5f`, заголовки
Playfair Display, текст Montserrat, радиусы и тени взяты из `Task 1st` без изменений.

## Как запустить

Страница открывается двойным щелчком по `index.html`. Если нужен сервер, из папки
`Solution`:

```bash
python -m http.server 8937
```

Дальше http://localhost:8937. Нужен интернет: и данные, и шрифты загружаются из сети.
Проверял в браузере, на ширине 1280, планшетной и 375 пикселей.

## Разбор кода

Запрос написан через `async/await`, как в девятом шаге методички. Версия на `then()`
из второго шага делает то же самое и выглядела бы так:

```js
fetch(API_URL)
    .then(response => response.json())
    .then(data => { /* data.results */ })
    .catch(error => { /* сообщение об ошибке */ });
```

Основная функция:

```js
async function getCharacters() {
    try {
        const response = await fetch(API_URL);
        if (!response.ok) {
            throw new Error("Ошибка сервера");
        }
        const data = await response.json();
        container.innerHTML = data.results.map(createCharacterCard).join("");
    } catch (error) {
        container.innerHTML = `<p class="error">Не удалось загрузить данные</p>`;
    }
}
```

Проверка `response.ok` здесь не формальность. Если сервер ответит 500 или 404, `fetch`
всё равно выполнится успешно, потому что для него запрос состоялся. Без проверки код
пошёл бы разбирать тело ошибки как список персонажей и упал бы позже, на
`data.results`, с невнятным сообщением. С проверкой любой плохой ответ сразу попадает в
`catch`.

Карточки собираются одной строкой через `map` и `join`, а не циклом с `+=`, как в
методичке. `container.innerHTML += ...` при каждом проходе заново разбирает уже
выведенную разметку и перезагружает картинки, с одной страницы в двадцать карточек это
заметно только в теории, но результат тот же.

Из полей персонажа выводятся имя, статус, вид, а дополнительно пол, происхождение,
локация, число эпизодов (длина массива `episode`) и дата создания записи. Дата в API
лежит строкой в формате ISO, поэтому проходит через `toLocaleDateString("ru-RU")`.

Сетка на четыре колонки по методичке, и на узких экранах она не годится: четыре колонки
на 375 пикселях превратились бы в нечитаемые полоски. Поэтому до 1024 пикселей колонок
две, до 560 одна.

Сообщение об ошибке я проверил отдельно, подменив `fetch` на функцию, которая падает, и
на функцию, которая отвечает статусом 500. В обоих случаях на странице появляется «Не
удалось загрузить данные», а после возвращения настоящего `fetch` карточки выводятся
снова.

## Теоретическая часть

**Fetch API** это встроенный в браузер механизм выполнения HTTP-запросов. Через него
JavaScript обращается к серверу и получает данные без перезагрузки страницы.

**fetch()** возвращает `Promise`, то есть обещание результата, которого пока нет. Когда
сервер ответит, промис выполнится и отдаст объект ответа `Response`.

**then()** обрабатывает успешный результат. В цепочке первый `then` превращает ответ в
JSON, второй получает уже готовые данные.

**catch()** срабатывает при ошибке в любом звене цепочки: упала сеть, пришёл
некорректный JSON, в обработчике выброшено исключение.

**finally()** выполняется в конце всегда, успешно закончился запрос или нет. Подходит
для действий, которые нужны в любом случае, например убрать индикатор загрузки.

**async/await** это другая запись той же работы с промисами. Функция помечается
`async`, а перед вызовом, который возвращает промис, ставится `await`. Код читается
сверху вниз, а ошибки ловятся обычным `try/catch`.

**Свойство ok** у ответа равно `true` для кодов 200-299. Его проверяют отдельно, потому
что `fetch` считает ошибкой только сетевую неудачу, а ответ 404 или 500 для него успех.

## Ответы на вопросы

**1. Что такое Fetch API?**

Встроенный в JavaScript механизм для выполнения HTTP-запросов к серверам и получения
данных. С его помощью страница обращается к API и обновляется без перезагрузки.

**2. Для чего используется функция fetch()?**

Чтобы отправить запрос по указанному адресу и получить ответ сервера. Вторым аргументом
можно передать настройки: метод, заголовки, тело. По умолчанию выполняется GET.

**3. Что возвращает fetch()?**

Промис, который при успехе выдаёт объект `Response`. Сами данные в нём ещё не
прочитаны, для этого вызывается `response.json()`.

**4. Что такое Promise?**

Объект, представляющий результат асинхронной операции, которая ещё не завершилась. Он
бывает в ожидании, выполненным успешно или отклонённым с ошибкой. Результат забирают
через `then`, `catch` и `finally`.

**5. Для чего используется then()?**

Для обработки успешно выполненной операции. Принимает функцию, в которую приходит
результат, и сам возвращает промис, поэтому вызовы выстраиваются в цепочку.

**6. Для чего используется catch()?**

Для обработки ошибок. Если на любом шаге цепочки произошла ошибка, выполнение
переходит в `catch`, и можно показать пользователю сообщение, как сделано здесь.

**7. Для чего используется finally()?**

Для кода, который нужен независимо от исхода: он срабатывает и после успеха, и после
ошибки. Результата запроса в него не передаётся.

**8. Чем отличается then/catch от async/await?**

Результат тот же, отличается запись. `then/catch` строит цепочку вызовов с функциями
обратного вызова, `async/await` позволяет писать асинхронный код как последовательный, а
ошибки ловить через `try/catch`. Второй вариант обычно проще читать, особенно когда
запросов несколько.

**9. Для чего используется response.json()?**

Чтобы прочитать тело ответа и преобразовать его из JSON-строки в объект JavaScript. Метод
тоже асинхронный и возвращает промис, поэтому перед ним нужен `await` или ещё один
`then`.

**10. Для чего используется свойство response.ok?**

Оно показывает, успешен ли HTTP-ответ: `true` для кодов от 200 до 299. `fetch` не
считает ошибкой ответы 404 и 500, поэтому проверять `ok` нужно самому и при `false`
выбрасывать исключение.

**11. Что такое JSON?**

Текстовый формат хранения и передачи структурированных данных. Построен на синтаксисе
объектов JavaScript, но не зависит от языка, поэтому API обычно отдают данные именно в
нём.

**12. Как получить данные из объекта JavaScript?**

Через точку по имени свойства: `character.name`. Для вложенных объектов точки
выстраиваются в цепочку, например `character.location.name`. Для имён, которых нет в
виде идентификатора, подходят квадратные скобки: `character["name"]`.
