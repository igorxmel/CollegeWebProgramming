## Быстрый старт

Сборка не нужна, это чистые HTML и CSS. Достаточно открыть файл в браузере:

```bash
start "" "Solution/index.html"
```

Если хочется отдать страницу через локальный сервер, из корня репозитория:

```bash
cd "Task 1st Responsive Layout with HTML5 and CSS3/Solution" && python -m http.server 8000
```

После этого страница открывается по адресу http://localhost:8000, остановка сервера по
`Ctrl+C`.

## Описание решения

```
Solution/
    index.html          разметка страницы
    css/
        style.css       все стили проекта
    images/
        hero-sneaker.svg
        brand.svg
        product-1.svg ... product-6.svg
```

Чтобы посмотреть результат, достаточно открыть `Solution/index.html` в браузере. Сборка и
локальный сервер не нужны, это чистые HTML и CSS без JavaScript.

Вместо растровых заглушек я нарисовал изображения в SVG: цветной круг и силуэт кроссовка в
стиле макета. Вектор не мылится на любых экранах и весит пару килобайт. Шрифты подключены с
Google Fonts, Playfair Display для крупных заголовков и Montserrat для текста. Если
интернета нет, подхватятся запасные шрифты из `font-family`.

Цвета, отступы, скругления и тени лежат в CSS-переменных в блоке `:root`, поэтому оттенок
меняется в одном месте, а не по всему файлу. Сам файл стилей поделён комментариями на
пронумерованные секции: токены, база, кнопки, логотип, шапка, первый экран и дальше по
блокам до медиазапросов.

Классы названы по БЭМ. Блоки: `header`, `hero`, `catalog`, `product-card`, `benefit`,
`review-card`, `contact-item`, `form-card`, `footer`, `button`, `logo`. Элементы пишутся
через два подчёркивания (`product-card__title`), модификаторы через два дефиса
(`button--primary`). Кнопка сделана одним блоком `button` с модификаторами вида, поэтому в
шапке, на первом экране, в карточках и в форме используется один и тот же код.

Адаптивность держится на трёх контрольных точках: 1024, 768 и 560 пикселей. На планшете
первый экран и секция о бренде складываются в одну колонку, на телефоне каталог и отзывы
становятся одноколоночными, меню переезжает на отдельную строку, а отступы контейнера
уменьшаются с 24 до 16 пикселей. В каталоге и отзывах колонки задаются через
`repeat(auto-fit, minmax(280px, 1fr))`, так что их количество подстраивается под ширину
экрана без отдельного медиазапроса.

Горизонтальной прокрутки нет ни на одной ширине. За это отвечают `box-sizing: border-box`
для всех элементов, `max-width: 100%` для картинок, `clamp()` для размеров заголовков и
`overflow-x: hidden` у `body`.

| Блок | Тег и класс | Как собран |
|---|---|---|
| Шапка | `<header class="header">` | Flexbox: логотип слева, меню справа, кнопка «Войти» с краю |

описание и подвал карточки с ценой и кнопкой.

## Теоретическая часть

### Клиентская и серверная части

Веб-приложение делится на две половины. Клиентская часть (frontend) загружается в браузер и
отвечает за внешний вид и реакцию на действия пользователя. Серверная часть (backend)
хранит и обрабатывает данные, работает с базой и отдаёт клиенту информацию через API.
Фреймворки вроде React или Vue решают задачи клиентской части, но опираются на те же HTML,
CSS и JavaScript.

### Семантическая разметка

Семантические теги говорят о назначении содержимого, а не только об оформлении. Вместо
россыпи `div` пишут `header` для шапки, `nav` для навигации, `main` для основного
содержимого, `section` для смыслового раздела, `article` для самостоятельной единицы
контента, `footer` для подвала.

Польза двойная: разработчику проще читать чужую разметку, а поисковые роботы и программы
чтения с экрана получают структуру документа и умеют перемещаться сразу по областям
страницы.

### Методология БЭМ

БЭМ расшифровывается как Блок, Элемент, Модификатор.

**Блок** это самостоятельный компонент интерфейса, который можно перенести в другое место
страницы и он не сломается: `card`, `button`, `header`.

**Элемент** это часть блока, которая вне него не имеет смысла. Пишется через два
подчёркивания: `card__title`, `card__image`.

**Модификатор** описывает вид или состояние. Пишется через два дефиса и ставится вместе с
основным классом: `card card--active`, `button button--primary`.

```html
<div class="product-card">
    <h3 class="product-card__title">Монстера</h3>
    <p class="product-card__description">Комнатное растение</p>
    <button class="product-card__button">Подробнее</button>
</div>
```

По имени класса сразу видно, к какому компоненту относится правило, а селекторы остаются
плоскими и не воюют друг с другом за приоритет.

### Flexbox

Flexbox (Flexible Box Layout) это модуль CSS для раскладки элементов вдоль одной оси.
Контейнер объявляется через `display: flex`, после чего его прямые потомки делят между собой
свободное место.

```css
.container {
    display: flex;
    justify-content: space-between;
    align-items: center;
}
```

`justify-content` распределяет элементы вдоль главной оси, `align-items` выравнивает их
поперёк. Направление главной оси меняется свойством `flex-direction`, перенос на новую
строку разрешается через `flex-wrap: wrap`.

### CSS Grid

Grid работает сразу по двум осям и предназначен для сеток. Колонки задаются свойством
`grid-template-columns`, расстояние между ячейками свойством `gap`.

```css
.products {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 20px;
}
```

Единица `1fr` это доля свободного места, поэтому три колонки получатся одинаковыми. Для
адаптивных каталогов чаще пишут иначе:

```css
.products {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
}
```

Браузер сам решает, сколько колонок поместится: каждая не уже 250 пикселей, а остаток ширины
делится поровну.

### Адаптивная вёрстка

Основной инструмент это медиазапросы:

```css
@media (max-width: 768px) {
    .header {
        flex-direction: column;
    }
}
```

Кроме них помогают относительные единицы (`%`, `fr`, `rem`, `vw`), функции `min()`, `max()`
и `clamp()`, а также `auto-fit` в гридах. Обязательное условие это мета-тег
`<meta name="viewport" content="width=device-width, initial-scale=1.0">`, без него мобильный
браузер отрисует страницу в виртуальном окне шириной около 980 пикселей и уменьшит её
целиком.

## Ответы на вопросы

Готового списка вопросов в методичке нет, есть требование ответить на вопросы по теории,
поэтому вопросы составлены по её разделам.

**1. Чем клиентская часть веб-приложения отличается от серверной?**

Клиентская часть выполняется в браузере и отвечает за интерфейс: разметку, оформление,
обработку действий пользователя. Серверная выполняется на сервере, хранит и обрабатывает
данные, обращается к базе и отдаёт результат клиенту через API.

**2. Что такое семантические теги и зачем они нужны?**

Это теги, отражающие смысл содержимого: `header`, `nav`, `main`, `section`, `article`,
`aside`, `footer`. Оформления они не добавляют, зато делают структуру документа понятной
разработчикам, поисковым системам и вспомогательным технологиям.

**3. Как расшифровывается БЭМ и как записываются его составляющие?**

Блок, Элемент, Модификатор. Блок это независимый компонент (`card`), элемент это его часть
через двойное подчёркивание (`card__title`), модификатор это вариант вида или состояние
через двойной дефис рядом с базовым классом (`card card--active`).

**4. Может ли элемент существовать без блока?**

Нет, элемент по определению часть конкретного блока. Если кусок интерфейса нужен сам по себе
в разных местах, это уже не элемент, а отдельный блок.

**5. Что делает свойство `display: flex`?**

Превращает элемент во flex-контейнер. Его прямые потомки раскладываются вдоль главной оси, к
ним становятся применимы `justify-content`, `align-items`, `gap`, `flex-grow`, `flex-shrink`
и `flex-basis`.

**6. Чем `justify-content` отличается от `align-items`?**

`justify-content` распределяет элементы вдоль главной оси, `align-items` выравнивает вдоль
поперечной. При `flex-direction: row` первое отвечает за горизонталь, второе за вертикаль,
при `column` оси меняются местами.

**7. В чём разница между Flexbox и CSS Grid?**

Flexbox одномерный и раскладывает элементы по одной оси. Grid двумерный, задаёт и колонки, и
строки. На практике их совмещают: Grid для общей сетки страницы или каталога, Flexbox для
содержимого внутри карточки.

**8. Что означает запись `repeat(auto-fit, minmax(250px, 1fr))`?**

Браузер создаёт столько колонок, сколько поместится, при условии что каждая не уже 250
пикселей, а оставшееся место делит между ними поровну. Получается адаптивная сетка без
медиазапросов.

**9. Что такое медиазапрос и как он записывается?**

Правило, которое применяет стили при выполнении условия, чаще всего по ширине области
просмотра: `@media (max-width: 768px) { ... }` или `@media (min-width: 768px) { ... }` при
подходе mobile first.

**10. Зачем нужен мета-тег viewport?**

Он говорит мобильному браузеру брать ширину области просмотра равной ширине устройства и
оставить начальный масштаб единичным. Без него телефон отрисует страницу в широком
виртуальном окне и уменьшит её, из-за чего мобильные медиазапросы не сработают.

**11. Почему стили лучше держать во внешнем файле, а не в атрибуте `style`?**

Внешний файл кешируется браузером, переиспользуется всеми страницами и правится в одном
месте. Инлайновые стили дублируются, ломают разделение структуры и оформления и имеют такой
высокий приоритет, что переопределить их можно почти только через `!important`.

**12. Из-за чего появляется горизонтальная прокрутка и как её убрать?**

Из-за элементов шире контейнера: фиксированная ширина в пикселях, длинная строка без
пробелов, отрицательные отступы, картинка без ограничения ширины, `100vw` при видимой
вертикальной полосе прокрутки. Лечится относительными единицами,
`box-sizing: border-box`, `max-width: 100%` для медиа и `flex-wrap: wrap` для рядов.
