## Описание решения

Методичка разрешает два варианта: сделать каталог игр по образцу или продолжить проект из
первых практических. Я взял второе, потому что весь курс крутится вокруг магазина
кроссовок «Dream Sneakers»: в четвёртой работе спроектирована база под него, в пятой она
наполнена данными. Поэтому API отдаёт кроссовки, а не игры, и модели в нём те же самые,
что лежат в таблице `product`.

```
Solution/
    package.json       зависимости и команда запуска
    app.js             сервер и все шесть маршрутов
    data.js            данные каталога
```

Данные я вынес в отдельный модуль. В методичке массив лежит прямо в `app.js`, но там он
один, а здесь наборов четыре, и файл с маршрутами превратился бы в простыню из данных, в
которой сами маршруты теряются. `data.js` экспортирует четыре массива, `app.js` забирает
их одной строкой через деструктуризацию.

В каталог попали только модели с `is_active = 1`. Снятые с продажи Puma Suede Classic и
Puma MB.03 из базы пятой работы в выдачу не идут, покупать их всё равно нельзя.

Рейтинг посчитан по таблице `review` той же базы: средний балл и число отзывов по каждой
модели. New Balance FuelCell отзывов не имеет и остаётся в списке с пустым баллом, как в
запросе с `LEFT JOIN` из пятой работы. Даты в новостях совпадают с `created_at` моделей.

## Как запустить

Express это внешний пакет, в отличие от модуля `http` из прошлой работы. Поэтому сначала
надо поставить зависимости:

```bash
npm install
```

Папка `node_modules` появится рядом, в репозиторий она не кладётся: её полностью
восстанавливает `npm install` по `package.json`. Дальше запуск:

```bash
npm start
```

или `node app.js`, это одно и то же. В терминале появится «Сервер запущен на порту 3000»,
после чего маршруты открываются в браузере. Останавливается сервер через Ctrl+C.

Проверял на Node.js 24.14.0 и Express 5.2.1.

## Маршруты

| Адрес | Что отдаёт | Тип ответа |
| --- | --- | --- |
| `/` | приветствие каталога | текст |
| `/about` | описание API | текст |
| `/sneakers` | список моделей в продаже | JSON |
| `/news` | новости о релизах | JSON |
| `/rating` | рейтинг моделей по отзывам | JSON |
| `/categories` | категории кроссовок | JSON |

Первые три это основное задание, остальные три дополнительное. В методичке последний
дополнительный маршрут назван `/genres`, но жанров у кроссовок нет, их место занимают
категории (беговые, повседневные, баскетбольные), это готовая таблица `category` из
четвёртой работы. По той же причине `/games` превратился в `/sneakers`.

Адрес, которого нет в списке, Express отдаёт с кодом 404. Отдельно это нигде не прописано,
обработчик по умолчанию срабатывает сам, когда ни один маршрут не подошёл.

## Разбор кода

Подключение фреймворка и создание приложения:

```js
const express = require("express");
const app = express();
```

`express()` возвращает объект приложения, на котором дальше объявляются маршруты. Сам по
себе он ещё ничего не слушает.

Маршрут это пара из адреса и функции-обработчика:

```js
app.get("/sneakers", (req, res) => {
    res.json(sneakers);
});
```

`app.get()` реагирует только на запросы методом GET по этому адресу. Обработчик получает
`req` с данными запроса и `res` для ответа. Разницу между `send()` и `json()` хорошо видно
по заголовкам: `res.send("строка")` уходит с `Content-Type: text/html`, а `res.json(массив)`
с `application/json`, и объект при этом сам превращается в JSON-строку, вручную
`JSON.stringify` звать не надо. Я это проверил, глядя на заголовки ответов.

Запуск такой же, как в прошлой работе:

```js
app.listen(PORT, () => {
    console.log(`Сервер запущен на порту ${PORT}`);
});
```

По сравнению с шестой работой разница в том, что там обработчик был один на все адреса и
разбирать `request.url` пришлось бы руками. Express делает это за меня: я просто описываю
маршруты, а он сам подбирает подходящий и возвращает 404, если ни один не подошёл.

## Теоретическая часть

**Express.js** это фреймворк для Node.js, который берёт на себя рутину вокруг встроенного
модуля `http`. Главное, что он даёт: маршрутизация, промежуточные обработчики
(middleware), удобные методы ответа и большая экосистема готовых модулей. Код получается
короче и читается лучше, чем на чистом `http`, поэтому на нём пишут и API, и серверную
часть сайтов.

**Маршрутизация** это сопоставление адреса запроса с кодом, который должен на него
ответить. Маршрут складывается из HTTP-метода и пути: `GET /sneakers` и `POST /sneakers`
это два разных маршрута, хотя путь один.

**Метод GET** запрашивает данные и ничего на сервере не меняет. Параметры он передаёт в
самом адресе, тела у него нет. Остальные методы в этой работе не нужны: каталог только
отдаёт данные.

**JSON** это формат обмена данными, который понимают и JavaScript, и почти любой другой
язык. Именно в нём API отдаёт списки, а клиент (браузер, мобильное приложение, другой
сервер) разбирает их у себя.

## Ответы на вопросы

**1. Что такое Express.js?**

Веб-фреймворк для Node.js, надстройка над встроенным модулем `http`. Берёт на себя
маршрутизацию, обработку запросов и формирование ответов, за счёт чего серверный код
пишется быстрее и выглядит проще.

**2. Для чего используется маршрутизация?**

Чтобы сервер понимал, какой код выполнить для конкретного адреса. Без неё один обработчик
отвечал бы одинаково на любой запрос, как в шестой работе, и адрес пришлось бы разбирать
вручную.

**3. Что делает метод app.get()?**

Регистрирует обработчик GET-запросов по указанному пути. Первым аргументом идёт адрес,
вторым функция, которая получает объект запроса и объект ответа и формирует ответ.

**4. В чем отличие send() от json()?**

`send()` отправляет что угодно: строку, HTML, буфер, и тип содержимого подбирает по
переданному значению (для строки это `text/html`). `json()` всегда преобразует аргумент в
JSON-строку и ставит `Content-Type: application/json`. Для API нужен именно `json()`,
иначе клиент получит данные, но не поймёт, что это JSON.

**5. Для чего используется listen()?**

Занимает порт и запускает ожидание входящих соединений. Пока `listen()` не вызван,
маршруты описаны, но сервер не работает. Вторым аргументом можно передать функцию, которая
сработает один раз после успешного запуска.

**6. Что такое URL-маршрут?**

Путь в адресе после имени хоста и порта, на который сервер умеет отвечать. В
`http://localhost:3000/sneakers` маршрут это `/sneakers`. Вместе с HTTP-методом он
однозначно определяет, какой обработчик вызовется.

**7. Что такое HTTP GET запрос?**

Запрос на получение данных с сервера. Тела у него нет, нужные параметры передаются прямо
в адресе, и сам он ничего на сервере не изменяет. Браузер отправляет именно GET, когда
открываешь адрес в адресной строке.
