# Практическая работа №10. Регистрация и авторизация пользователей в Node.js

Работа продолжает тему Node.js и MySQL. В девятой работе сервер только читал данные из
базы, здесь он создаёт пользователей, проверяет пароль при входе и выдаёт JWT-токен.
Дополнительно сделана страница с формами регистрации и входа и списком пользователей.

## Описание решения

```
Solution/
    web_project.sql   база и таблица users
    db.js             пул подключений к MySQL
    app.js            сервер и маршруты
    public/
        index.html    формы регистрации и входа, список пользователей
        styles.css    оформление страницы
        main.js       запросы к API и обновление списка
    package.json      зависимости и команда запуска
```

База взята из методички: `web_project` с таблицей `users`. В девятой работе была
`games_db`, здесь она отдельная, чтобы пользователи не смешивались с играми. Методичка
разрешает взять базу своего проекта, но схема таблицы описана явно, поэтому сделана она.

## Как запустить

Нужна работающая база. В репозитории она поднимается через `docker-compose.yml`:

```bash
docker compose up -d
```

MySQL слушает порт 3307, Adminer доступен на http://localhost:8081. На чистом томе
`web_project.sql` выполняется сам, потому что подключён в `docker-compose.yml`. Если база
уже создана раньше, скрипт можно выполнить в Adminer: сервер `db`, пользователь `root`,
пароль `root`, вкладка SQL.

Дальше из папки `Solution`:

```bash
npm install
npm start
```

Сервер запустится на http://localhost:3000. В консоли должно появиться:

```
Подключение к MySQL установлено
Сервер запущен: http://localhost:3000
```

Для OpenServer в `db.js` меняются порт и пароль: порт из настроек MySQL, пароль пустой.

## Маршруты

| Метод | Адрес | Что делает |
| --- | --- | --- |
| POST | `/register` | Проверяет поля, хеширует пароль и добавляет пользователя |
| POST | `/login` | Ищет пользователя, сравнивает пароль и возвращает JWT |
| GET | `/users` | Возвращает всех пользователей без паролей |
| GET | `/users/:id` | Возвращает одного пользователя по идентификатору |
| DELETE | `/users/:id` | Удаляет пользователя по идентификатору |

## Разбор кода

### Подключение к MySQL

`db.js` создаёт пул подключений:

```js
const db = mysql.createPool({
    host: "localhost",
    user: "root",
    password: "root",
    database: "web_project",
    port: 3307,
    charset: "utf8mb4"
});
```

Пул переиспользует соединения, поэтому на каждый запрос не открывается новый сокет.
Пакет `mysql2/promise` возвращает промисы, и в маршрутах можно писать `await db.query()`.
Порт 3307 указан для контейнера из этого репозитория, у OpenServer порт другой.
`utf8mb4` нужен, чтобы русские имена сохранялись без искажений.

Запросы везде используют подстановки `?`, а не склейку строк. Значения передаются
отдельным массивом, и драйвер сам экранирует их. Так ввод пользователя не может изменить
текст запроса.

### Регистрация

Маршрут `POST /register` сначала проверяет, что пришли все поля:

```js
if (!name || !email || !password) {
    return res.status(400).json({
        message: "Заполните все поля"
    });
}
```

Потом ищет пользователя с таким email. Если запись уже есть, возвращается 400. Если нет,
пароль хешируется и вставляется новая строка:

```js
const hashedPassword = await bcrypt.hash(password, 10);

await db.query(
    "INSERT INTO users (name, email, password) VALUES (?, ?, ?)",
    [name, email, hashedPassword]
);
```

Второй аргумент `bcrypt.hash()` это число раундов соли. Десять раундов дают хеш длиной
60 символов, поэтому в таблице под пароль отведено `VARCHAR(255)`. В базу попадает
только хеш, исходный пароль нигде не сохраняется. Ответ 201 означает, что запись создана.

### Авторизация

`POST /login` ищет пользователя по email и сравнивает пароль:

```js
const match = await bcrypt.compare(password, user.password);

if (!match) {
    return res.status(400).json({
        message: "Неверный пароль"
    });
}
```

`bcrypt.compare()` сам извлекает соль из хеша и проверяет введённый пароль. Если email не
найден, возвращается 404, если найден, но пароль не совпал, 400. После успешной проверки
создаётся токен:

```js
const token = jwt.sign(
    { id: user.id },
    JWT_SECRET,
    { expiresIn: "1h" }
);
```

В токен попадает идентификатор пользователя, срок жизни один час. Подпись сделана
секретным ключом, поэтому токен нельзя незаметно изменить. Клиент получает его в ответе
и может отправлять в заголовке `Authorization` на защищённые маршруты. В этой работе
защищённых маршрутов нет, токен только создаётся и возвращается.

### Пользователи

`GET /users` выбирает только три столбца:

```js
const [users] = await db.query(
    "SELECT id, name, email FROM users ORDER BY id"
);
```

Столбец `password` в выборку не попадает, поэтому хеши не уходят клиенту. `GET /users/:id`
берёт идентификатор из `req.params.id`, а если строки нет, возвращает 404. `DELETE`
выполняет удаление и проверяет `affectedRows`: ноль означает, что пользователя с таким
номером не было.

### Интерфейс

Страница в `public` отправляет данные через `fetch`. Форма регистрации собирает поля
через `FormData`, превращает их в объект и отправляет JSON:

```js
const result = await request("/register", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data)
});
```

После успешного ответа форма очищается, а список пользователей перезагружается. Список
строится через `createElement` и `textContent`, поэтому имя или email с символами `<` и
`>` останутся текстом и не превратятся в разметку. У каждой строки есть кнопка удаления,
она отправляет `DELETE /users/:id`. Сообщения об успехе и ошибке выводятся над формами,
токен после входа показывается в отдельном блоке.

## Проверка

Сервер проверялся на запущенной базе. Запросы и ответы:

| Запрос | Код | Ответ |
| --- | --- | --- |
| `POST /register` с именем, email и паролем | 201 | `{"message":"Пользователь зарегистрирован"}` |
| `POST /register` с тем же email | 400 | `{"message":"Пользователь с таким email уже существует"}` |
| `POST /register` без пароля | 400 | `{"message":"Заполните все поля"}` |
| `POST /login` с верным паролем | 200 | `{"message":"Авторизация успешна","token":"..."}` |
| `POST /login` с неверным паролем | 400 | `{"message":"Неверный пароль"}` |
| `POST /login` с неизвестным email | 404 | `{"message":"Пользователь не найден"}` |
| `GET /users` | 200 | массив объектов `id`, `name`, `email` |
| `GET /users/1` | 200 | один объект без пароля |
| `GET /users/999` | 404 | `{"message":"Пользователь не найден"}` |
| `DELETE /users/1` | 200 | `{"message":"Пользователь удален"}` |
| `DELETE /users/1` повторно | 404 | `{"message":"Пользователь не найден"}` |

В таблице `users` после регистрации лежит хеш вида
`$2b$10$YFQC6lyuu8LmwBtYSWrs/.sGlu3CLRVtqHHnda3euuewAbuji1Tzm`, а не исходный пароль.
Страница проверялась в браузере: регистрация, вход, неверный пароль, повторная регистрация
и удаление работают, ошибок в консоли нет.

## Теоретическая часть

Регистрация создаёт новую учётную запись. Пользователь присылает имя, email и пароль,
сервер проверяет данные, хеширует пароль и добавляет строку в таблицу. Авторизация это
проверка уже существующей учётной записи при входе. Сервер находит пользователя по email,
сравнивает пароль с хешем и при успехе выдаёт токен. Регистрация происходит один раз,
авторизация при каждом входе.

Пароль нельзя хранить открытым текстом. Если база утечёт, злоумышленник получит готовые
пароли, а пользователи часто используют один и тот же пароль на разных сайтах. Хеширование
превращает пароль в строку фиксированной длины, из которой нельзя восстановить исходное
значение. bcrypt специально сделан медленным и добавляет соль, поэтому одинаковые пароли
дают разные хеши, а перебор вариантов требует много времени.

JWT это подписанный токен, в котором передаются данные о пользователе. Он состоит из
заголовка, полезной нагрузки и подписи, разделённых точками. Сервер создаёт токен после
успешного входа, а на защищённых маршрутах может проверять его подпись. В полезной
нагрузке здесь лежит только идентификатор пользователя и срок действия.

Запросы к базе асинхронные. `Promise` представляет результат, который появится позже:
успешное значение или ошибку. `async` объявляет функцию, которая всегда возвращает
промис, а `await` приостанавливает её до получения результата. `try...catch` перехватывает
ошибки внутри такой функции, поэтому сбой базы не роняет сервер, а превращается в ответ
500.

Express кладёт разобранный JSON в `req.body`, а части адреса в `req.params`. Из `req.body`
берутся имя, email и пароль при регистрации и входе. Из `req.params.id` берётся номер
пользователя в маршрутах `/users/:id`.

## Ответы на вопросы

**1. Что такое регистрация пользователя?**

Создание новой учётной записи. Пользователь передаёт свои данные, сервер проверяет их и
сохраняет в базе, после чего с этой учётной записью можно входить в систему.

**2. Чем регистрация отличается от авторизации?**

Регистрация создаёт учётную запись и происходит один раз. Авторизация проверяет уже
созданную учётную запись при входе и происходит при каждом входе в систему.

**3. Для чего используется bcrypt?**

Для безопасной работы с паролями. Он хеширует пароль перед сохранением и сравнивает
введённый пароль с сохранённым хешем при входе. Встроенная соль и медленный алгоритм
затрудняют подбор паролей.

**4. Почему нельзя хранить пароль в базе данных в обычном виде?**

Потому что при утечке базы злоумышленник сразу получит все пароли. Люди часто используют
один пароль на разных сайтах, поэтому пострадают и другие учётные записи. Хеш нельзя
прочитать и превратить обратно в пароль.

**5. Что такое хеширование?**

Преобразование данных в строку фиксированной длины с помощью односторонней функции.
Из исходного пароля хеш получается быстро, а восстановить пароль по хешу практически
невозможно. Если соль одна и та же, одинаковые данные дают одинаковый хеш, но bcrypt
создаёт случайную соль, поэтому хеши разных записей различаются.

**6. Для чего используется bcrypt.hash()?**

Для получения хеша пароля перед записью в базу. В функцию передают пароль и число
раундов, она добавляет соль и возвращает строку, которую можно сохранить в столбце
`password`.

**7. Для чего используется bcrypt.compare()?**

Для проверки пароля при входе. Она сравнивает введённый пароль с хешем из базы и
возвращает `true`, если они соответствуют друг другу, и `false`, если нет.

**8. Что такое JWT?**

JSON Web Token, подписанный токен с данными о пользователе. Состоит из заголовка,
полезной нагрузки и подписи. Сервер выдаёт его после успешного входа и может проверять
подпись при следующих запросах.

**9. Для чего используется jsonwebtoken?**

Для создания и проверки JWT. В этой работе через `jwt.sign()` создаётся токен с
идентификатором пользователя и сроком действия. Библиотека также умеет проверять подпись
через `jwt.verify()`.

**10. Что такое Promise?**

Объект, который представляет результат асинхронной операции. Сначала он находится в
состоянии ожидания, потом переходит в состояние успеха со значением или в состояние
ошибки. С промисами можно работать через `then`, `catch` или через `async` и `await`.

**11. Для чего используется async?**

Чтобы объявить функцию, внутри которой можно использовать `await`. Такая функция всегда
возвращает промис, а её результат оборачивается в успешное значение или в ошибку.

**12. Для чего используется await?**

Чтобы дождаться результата промиса и продолжить выполнение функции после него. В этой
работе `await db.query()` ждёт ответа базы, а `await bcrypt.hash()` ждёт готовый хеш.

**13. Для чего используется try...catch?**

Для обработки ошибок. В `try` выполняется запрос к базе или проверка пароля, в `catch`
перехватывается ошибка. Без него сбой базы привёл бы к необработанному исключению, а с ним
сервер возвращает понятный ответ 500.

**14. Для чего используется req.body?**

Для получения данных, которые клиент отправил в теле запроса. Здесь из `req.body`
берутся `name`, `email` и `password` при регистрации и `email` и `password` при входе.
Чтобы объект появился, на сервере подключён `express.json()`.

**15. Для чего используется req.params?**

Для получения параметров из адреса маршрута. В маршруте `/users/:id` значение `:id`
попадает в `req.params.id`. По нему сервер ищет или удаляет нужного пользователя.

**16. Что делает маршрут POST /register?**

Принимает имя, email и пароль, проверяет, что все поля заполнены и такого email ещё нет,
хеширует пароль через bcrypt и добавляет пользователя в таблицу `users`. При успехе
возвращает 201 и сообщение о регистрации.

**17. Что делает маршрут POST /login?**

Принимает email и пароль, ищет пользователя по email, сравнивает пароль с хешем через
`bcrypt.compare()` и при успехе создаёт JWT через `jwt.sign()`. В ответе возвращаются
сообщение об успешной авторизации и токен.
