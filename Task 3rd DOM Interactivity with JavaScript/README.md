## Быстрый старт

Сборка не нужна, достаточно открыть файл в браузере:

```bash
start "" "Solution/index.html"
```

Через локальный сервер, из корня репозитория:

```bash
cd "Task 3rd DOM Interactivity with JavaScript/Solution" && python -m http.server 8000
```

Страница будет доступна по адресу http://localhost:8000, остановка сервера по `Ctrl+C`.

Проверять интерактив удобнее в узком окне: бургер-меню включается на ширине меньше 768
пикселей, режим адаптива в браузере открывается по `Ctrl+Shift+M`.

Что изменилось в разметке по сравнению с первой работой:

- в шапке появились переключатель темы, кнопка «Оставить заявку» и бургер;
- добавились две секции, «Галерея» и «Часто задаваемые вопросы»;

и молча выходит, если нужного элемента на странице нет, поэтому компонент можно перенести на
другую страницу, ничего не сломав.

## Разбор заданий

**Задание 1. Анимация кнопок.** Блок `.button` получил `transition` по `background-color`,
`color`, `border-color`, `transform` и `box-shadow`. При наведении кнопка немного
поднимается и увеличивается (`translateY(-2px) scale(1.04)`), появляется тень в цвет
акцента, при нажатии кнопка слегка проседает.

**Задание 2. Модальное окно.** Кнопки с атрибутом `data-modal-open` в шапке, на первом
экране и в подвале открывают окно с полями имени, телефона и комментария. Открытие это
добавление класса `modal--open`, за анимацию отвечает CSS: подложка проявляется через
`opacity`, окно выезжает через `transform`. Пока окно открыто, на `body` висит класс
`is-locked` с `overflow: hidden`, иначе фон прокручивается под модалкой. Закрыть окно можно
крестиком, клавишей `Escape` и кликом по затемнённой области.

Отправка формы перехватывается через `preventDefault()`, страница не перезагружается. Вместо
формы показывается сообщение об отправке, через 2,5 секунды окно закрывается и форма
возвращается в исходное состояние. Настоящей отправки на сервер нет, серверная часть будет в
следующих работах.

**Задание 3. Закрытие по фону.** Подложка `.modal__overlay` это отдельный элемент под окном,
растянутый на весь экран. На нём тот же атрибут `data-modal-close`, что и на крестике,
поэтому обработчик один. Клик по самому окну до подложки не доходит, потому что окно лежит
выше и является отдельным узлом, а не потомком подложки.

**Задание 4. Бургер-меню.** На экранах уже 768 пикселей меню превращается в панель, которая
выпадает из-под шапки, кнопка бургера показывается только в этом диапазоне. Три полоски
превращаются в крестик поворотом первой и третьей на 45 градусов и скрытием средней. Меню
закрывается при клике по ссылке и при увеличении окна шире 768 пикселей, иначе на десктопной
ширине остался бы висеть невидимый открытый блок.

**Задание 5. Кнопка «Наверх».** Круглая кнопка в правом нижнем углу. Обработчик события
`scroll` сравнивает `window.scrollY` с порогом в 400 пикселей и переключает класс
`scroll-top--visible`. Плавная прокрутка сделана через
`window.scrollTo({ top: 0, behavior: "smooth" })`.

**Задание 6. Аккордеон.** Блок «Часто задаваемые вопросы» из пяти пунктов. Одновременно
открыт может быть только один: перед открытием нового остальные закрываются, повторный клик
по открытому вопросу его сворачивает. Плюс справа превращается в минус поворотом
вертикальной чёрточки на 90 градусов с одновременным исчезновением.

Высота ответа анимируется через `max-height`. Анимировать `height: auto` браузер не умеет,
поэтому при открытии в стиль панели подставляется её реальная высота `panel.scrollHeight`, а
при закрытии значение убирается и панель схлопывается до нуля.

**Задание 7. Переключение темы.** Описано отдельным разделом ниже.

**Задание 8. Галерея.** Шесть миниатюр, клик по любой меняет большое изображение и подпись
под ним. Путь к картинке и название лежат в `data-`атрибутах кнопки и читаются через
`dataset`. Активная миниатюра подсвечивается рамкой акцентного цвета. Смена не мгновенная:
сначала картинке добавляется класс с нулевой прозрачностью, через 150 миллисекунд
подменяется `src` и класс снимается, получается затухание вместо рывка.

## Как устроено переключение темы

Все цвета ещё в первой работе были вынесены в CSS-переменные, поэтому тема переключается
заменой значений, а не переписыванием правил. Светлая тема живёт в `:root`, тёмная в
селекторе `[data-theme="dark"]`, а кнопка в шапке ставит или снимает атрибут `data-theme` у
элемента `<html>`.

Переменные разделены на три группы. Первая это обычные цвета интерфейса: фон, поверхность
карточек, текст, границы. Вторая это пара `--color-invert` и `--color-on-invert`, контрастная
связка для кнопок: на светлой теме кнопка тёмная с белым текстом, на тёмной наоборот. Третья
это цвета блоков, которые тёмные всегда независимо от темы, то есть секция «О бренде» и
подвал. Их переменные не переопределяются, поэтому эти блоки выглядят одинаково в обоих
режимах.

Выбор сохраняется в `localStorage` и восстанавливается при следующем заходе. Иллюстрация на
первом экране это чёрный кроссовок на прозрачном фоне, на тёмном фоне он сливался бы с
подложкой, поэтому для тёмной темы к нему применяется `filter: invert(1)`.

## Теоретическая часть

### Зачем нужен JavaScript на странице

HTML задаёт структуру, CSS отвечает за оформление, JavaScript добавляет поведение. С его
помощью страница меняет содержимое, реагирует на нажатия и ввод, открывает и закрывает меню,
показывает всплывающие окна, проверяет формы, анимирует элементы и обменивается данными с
сервером без перезагрузки.

Подключается скрипт отдельным файлом перед закрывающим `</body>`:

```html
<script src="js/main.js"></script>
```

К этому моменту разметка уже разобрана браузером, и скрипт видит все элементы. Если
поместить его в `<head>` без атрибутов `defer` или `async`, `document.querySelector` вернёт
`null`, потому что элементов ещё не существует.

### DOM

DOM (Document Object Model) это представление HTML-документа в виде дерева объектов. Каждый
тег становится узлом, у узлов есть родители, потомки и соседи. Через DOM скрипт получает
доступ к любому элементу и может менять его содержимое, атрибуты, классы и стили, а также
создавать и удалять узлы.

```js
document.getElementById("modal");             // по идентификатору
document.querySelector(".accordion__item");   // первый по CSS-селектору
document.querySelectorAll(".gallery__thumb"); // все по CSS-селектору
```

`querySelector` и `querySelectorAll` принимают любой CSS-селектор, поэтому используются
чаще остальных. Первый возвращает элемент или `null`, второй всегда возвращает список,
возможно пустой.

### События и addEventListener

Событие это сигнал о том, что на странице что-то произошло: пользователь нажал кнопку, ввёл
текст, прокрутил страницу, отправил форму, браузер закончил загрузку. Часто используемые
события: `click`, `input`, `change`, `submit`, `mouseover`, `mouseout`, `scroll`, `keydown`.

```js
const button = document.querySelector(".btn");

button.addEventListener("click", () => {
    console.log("Кнопка нажата");
});
```

Первый аргумент это имя события, второй функция-обработчик. В обработчик приходит объект
события: `event.target` это элемент, на котором событие случилось, `event.key` это нажатая
клавиша, `event.preventDefault()` отменяет стандартное поведение браузера.

### Управление внешним видом через классы

Менять оформление напрямую из скрипта (`element.style.backgroundColor = "red"`) можно, но
это смешивает стили с логикой. Правильнее описать состояние отдельным CSS-классом, а из
JavaScript только переключать его:

```js
element.classList.add("modal--open");
element.classList.remove("modal--open");
element.classList.toggle("nav--open");
element.classList.contains("nav--open");
```

Оформление остаётся в CSS, скрипт отвечает только за состояние. Если у класса есть
`transition`, переход произойдёт плавно.

### CSS-переходы и анимации

`transition` описывает плавный переход свойства из одного значения в другое, когда оно
меняется, например при наведении или при добавлении класса:

```css
.button {
    transition: background-color 0.25s ease, transform 0.25s ease;
}
```

`animation` вместе с `@keyframes` описывает более сложный сценарий с несколькими
промежуточными состояниями, зацикливанием и задержками. Плавнее всего анимируются
`transform` и `opacity`, потому что они не заставляют браузер пересчитывать раскладку
страницы.

## Ответы на вопросы

**1. Для чего используется JavaScript?**

Это язык, который отвечает за поведение страницы. Он обрабатывает действия пользователя,
меняет содержимое и оформление элементов, проверяет и отправляет формы, показывает модальные
окна и меню, анимирует интерфейс, запрашивает данные у сервера без перезагрузки. За
пределами браузера на нём пишут и серверную часть, например на Node.js.

**2. Что такое событие?**

Сигнал о том, что на странице что-то произошло. Источником может быть пользователь (клик,
ввод текста, прокрутка, нажатие клавиши), сам браузер (загрузка страницы, изменение размера
окна) или таймер. Программа не опрашивает состояние в цикле, а подписывается на нужные
события и реагирует, когда они происходят.

**3. Для чего применяется `addEventListener()`?**

Чтобы назначить элементу обработчик события. Метод принимает имя события и функцию, которая
выполнится при его наступлении. В отличие от записи `element.onclick = ...` он позволяет
повесить на один элемент несколько обработчиков одного события, не затирая предыдущие,
поддерживает третий параметр с настройками (`once`, `capture`, `passive`) и снимается
методом `removeEventListener()`.

**4. Что такое DOM?**

Объектная модель документа, то есть представление HTML-страницы в виде дерева объектов,
которое браузер строит при разборе разметки. Каждый тег, текст и комментарий это узел с
родителем и потомками. DOM это интерфейс между разметкой и скриптом: через него JavaScript
читает и меняет содержимое, атрибуты, классы и стили, добавляет и удаляет элементы.

**5. Как получить элемент страницы через JavaScript?**

Чаще всего через `document.querySelector(selector)` для одного элемента и
`document.querySelectorAll(selector)` для всех подходящих, оба принимают обычный
CSS-селектор. Есть и более старые методы: `getElementById`, `getElementsByClassName`,
`getElementsByTagName`. Искать можно не только по всему документу, но и внутри конкретного
элемента: `item.querySelector(".accordion__panel")`.

**6. Для чего используются классы в JavaScript?**

Чаще всего под этим понимают работу с CSS-классами через свойство `classList`. Класс
описывает состояние элемента (`modal--open`, `nav--open`, `accordion__item--open`), скрипт
его добавляет, убирает или переключает методами `add`, `remove`, `toggle` и `contains`, а
оформление и анимации остаются в CSS.

Отдельно в языке есть классы как синтаксис ООП (`class Slider { constructor() {...} }`) для
описания шаблона объектов с полями и методами. В этой работе они не понадобились, логика
разбита на функции.

**7. Что такое модальное окно?**

Всплывающее окно поверх страницы, которое перехватывает внимание и не даёт работать с
содержимым под ним, пока не будет закрыто. Обычно состоит из полупрозрачной подложки и
самого окна. Применяется для форм заявки и авторизации, подтверждения удаления, просмотра
изображений. Закрываться оно должно тремя способами: кнопкой, клавишей `Escape` и кликом по
подложке, а фон под ним не должен прокручиваться.

**8. Для чего используется `preventDefault()`?**

Метод объекта события отменяет действие браузера по умолчанию. Для отправки формы это
перезагрузка страницы, для клика по ссылке переход по адресу, для нажатия правой кнопкой
показ контекстного меню. В этой работе `preventDefault()` вызывается при отправке формы в
модальном окне, чтобы показать сообщение прямо на странице, а не потерять всё при
перезагрузке.

**9. Что такое CSS-анимация?**

Плавное изменение значений свойств во времени, которое выполняет сам браузер. Есть два
инструмента. `transition` описывает переход свойства между двумя состояниями и запускается,
когда значение меняется. `animation` вместе с правилом `@keyframes` задаёт сценарий с
промежуточными кадрами, длительностью, задержкой и повторами. Плавнее всего анимируются
`transform` и `opacity`.

**10. Чем отличается `display: none` от `visibility: hidden`?**

`display: none` полностью убирает элемент из потока: он не занимает места, соседи
сдвигаются, анимировать переход нельзя. `visibility: hidden` делает элемент невидимым, но
место под него остаётся, а само свойство участвует в переходах, поэтому его удобно
комбинировать с `opacity` для плавного появления. В этой работе модальное окно и кнопка
«наверх» скрыты именно связкой `opacity` и `visibility`, иначе исчезновение было бы резким.
Есть и третий вариант, `opacity: 0` без `visibility`: элемент невидим, но продолжает
принимать клики.
