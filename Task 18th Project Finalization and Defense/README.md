# ПР №18. Завершение проекта и защита

Финальная версия Dream Sneakers объединяет каталог, корзину, оформление заказа, форму обращений и панель обработки. Подготовлены презентация и сценарий выступления.

## Как запустить

Нужны Node.js 22.12 или новее и Docker. Из корня CollegeWebProgramming запустить:

```powershell
docker compose up -d --wait
docker compose exec -T db mysql --default-character-set=utf8mb4 -uroot -proot -e "source /docker-entrypoint-initdb.d/17-dream-sneakers.sql"
```

При первом запуске MySQL создаёт таблицы автоматически. Вторая команда добавляет
их в уже существующую базу и сохраняет данные. Adminer: http://localhost:8081,
сервер `db`, учебный логин `root` и пароль `root`, база `dream_sneakers`.

В папке `Solution` скопировать `.env.example` в `.env`. Подключение уже настроено
на MySQL из Docker (`127.0.0.1:3307`). Заполнить `ADMIN_PASSWORD` для входа в панель
и задать случайный `JWT_SECRET` длиной от 32 символов.

~~~powershell
npm ci
npm run server
~~~

В другом окне, из той же папки:

~~~powershell
npm run dev
~~~

Открыть адрес Vite. Панель заявок находится на /admin. Для проверки сборки
выполнить npm run build.

## Проверка

Порядок показа: каталог и поиск, мобильный вид, заказ двух пар, отправка заявки, вход в панель и смена статуса. План выступления лежит в Solution/Defense.md.

## Контрольные вопросы

1. **Для чего проводится тестирование веб-приложения?** Тестирование выявляет ошибки в интерфейсе, данных и действиях пользователя.
2. **Что такое адаптивный дизайн?** Адаптивный дизайн подстраивает компоновку под ширину экрана и способ ввода.
3. **Какие основные ошибки необходимо проверить перед запуском приложения?** Проверяют запуск, подключение к БД, формы и запросы, сохранение данных, доступ к панели и обработку ошибок.
4. **Как взаимодействуют клиентская часть, сервер и база данных?** React вызывает API Express, сервер читает и записывает MySQL и возвращает результат в JSON.
5. **Какие сведения необходимо включить в презентацию проекта?** В презентации показывают назначение проекта, технологии, основные сценарии, результаты проверки и место для живой демонстрации.
6. **Для чего используется README-файл?** README объясняет, что делает проект, какие зависимости нужны и как его запустить.
7. **Какие этапы необходимо выполнить перед публикацией веб-приложения?** Проверяют конфигурацию, собирают проект, прогоняют основные сценарии и готовят данные для демонстрации.
