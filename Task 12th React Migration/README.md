# ПР №12. Введение в React и создание компонентов

Лендинг магазина Dream Sneakers из первой практической работы, перенесённый на React: страница разбита на компоненты, стили остались прежними, внешний вид совпадает с HTML-версией. Проект собран на Vite.

```

    public/

    src/
        main.jsx
        App.jsx
        index.css          стили из ПР №1
        components/
            Logo.jsx
            Header.jsx
            Hero.jsx

            Brand.jsx
            Benefit.jsx
            Reviews.jsx
            ReviewCard.jsx
            Contacts.jsx
            ContactItem.jsx
            ContactForm.jsx
            Footer.jsx
```

Структура такая же, как у проекта Vite с шаблоном React и JavaScript: корень с `index.html`, `package.json` и `vite.config.js`, в `src` лежат `main.jsx`, `App.jsx` и `index.css`, свои компоненты вынесены в `components`. Картинки лежат в `public/images`, поэтому в разметке на них ссылки вида `/images/product-1.svg`. Шрифты подключаются из Google Fonts в `index.html`, как это было в HTML-версии.

## Как запустить

Перейти в папку решения:

```
cd Solution
```

Установить зависимости:

```
npm install
```

Запустить сервер разработки:

```
npm run dev
```

Vite напишет адрес, обычно это `http://localhost:5173`. Production-сборка делается командой:

```
npm run build
```

Интерактивность из ПР №3 сюда не переносилась: методичка просит именно разбить на компоненты готовую страницу, а состояние и события появятся дальше.

## Компоненты

В `App.jsx` остаётся только порядок блоков: шапка, внутри `main` пять секций, подвал.

```jsx
function App() {
    return (
        <>
            <Header />
            <main>
                <Hero />
                <ProductList />
                <Brand />
                <Reviews />
                <Contacts />
            </main>
            <Footer />
        </>
    );
}
```

Каждый блок макета стал отдельным компонентом. Шапка, главный экран и подвал это `Header`, `Hero` и `Footer`. Логотип встречается и в шапке, и в подвале, поэтому вынесен в `Logo` с параметром `light`, который включает светлый вариант. Каталог это `ProductList` и повторяющийся `ProductCard`. Блок «О бренде» собран из `Brand` и трёх `Benefit`, отзывы из `Reviews` и трёх `ReviewCard`, контакты из `Contacts`, трёх `ContactItem` и `ContactForm`. Всего тринадцать компонентов при минимуме в четыре.

Карточка товара это тот самый повторяющийся элемент из шага 7. Для неё создан компонент `ProductCard`, а `ProductList` выводит его шесть раз подряд. Методичка разрешает на этом этапе одинаковое содержимое карточек, передача разных данных появится в следующей работе, поэтому все шесть карточек показывают одну модель, Urban Classic.

```jsx
function ProductList() {
    return (
        <section className="catalog" id="catalog">
            <div className="container">
                <div className="section-head">
                    <h2 className="section-head__title section-head__title--underlined">Каталог</h2>
                    <a className="section-head__link" href="#catalog">Смотреть все &rarr;</a>
                </div>

                <div className="catalog__grid">
                    <ProductCard />
                    <ProductCard />
                    <ProductCard />
                    <ProductCard />
                    <ProductCard />
                    <ProductCard />
                </div>
            </div>
        </section>
    );
}
```

В остальных повторяющихся блоках (преимущества, отзывы, пункты контактов) содержимое в макете разное, и там данные уже передаются через props, а сами списки лежат массивами рядом с компонентом-контейнером. Так страница в этих секциях не отличается от макета.

## Перенос стилей и разметки

CSS переехал без изменений: в нём уже были классы по БЭМ, а они не зависят от того, в HTML лежит разметка или в JSX. Файл подключается один раз в `main.jsx` через `import "./index.css"`.

Менять пришлось только разметку. `class` стал `className`, `for` у подписей формы стал `htmlFor`, `rows="4"` остался строкой, как в HTML. Атрибуты SVG записываются в camelCase: `stroke-width` превратился в `strokeWidth`, `stroke-linejoin` в `strokeLinejoin`. Одиночные теги вроде `img`, `input` и `br` в JSX обязательно закрываются слэшем. Звёзды в отзыве собираются из числа: оценка 4 даёт четыре закрашенные и одну пустую.

```jsx
const stars = "★".repeat(rating) + "☆".repeat(5 - rating);
```

Форма осталась такой же, как в ПР №1, с атрибутами `required` и без обработчика отправки. Работа с формами в React в методичке не затрагивается.

## Теоретическая часть

React это JavaScript-библиотека для создания пользовательских интерфейсов. Интерфейс в ней разбивается на компоненты, независимые части, каждая из которых отвечает за свой кусок страницы и может использоваться повторно. Вместо одного большого HTML-документа получается дерево компонентов.

Компонент в React это обычная функция, которая возвращает разметку. Имя компонента пишется с заглавной буквы, чтобы React отличал его от обычных тегов. Один компонент можно вложить в другой так же, как тег.

Разметка внутри функции записывается на JSX. Это расширение синтаксиса JavaScript, внешне похожее на HTML. Отличий несколько. Вместо `class` пишется `className`, потому что `class` в JavaScript зарезервировано. У компонента должен быть один корневой элемент, поэтому несколько соседних элементов заворачивают в пустой фрагмент `<>...</>`. Все теги закрываются. JavaScript-выражения вставляются в фигурных скобках.

Проект создаётся сборщиком Vite командой `npm create vite@latest`. В `src` лежат `main.jsx`, где React подключается к элементу `#root` на странице, и `App.jsx`, главный компонент приложения. Собственные компоненты складываются в папку `components`. Сервер разработки запускается командой `npm run dev`.

## Ответы на вопросы

**1. Что такое React?**

JavaScript-библиотека с открытым кодом для создания пользовательских интерфейсов. Она строит страницу из компонентов и обновляет только те части, которые изменились.

**2. Для чего используются компоненты?**

Чтобы разбить интерфейс на небольшие независимые части. Каждый компонент отвечает за свой блок страницы, его проще читать, менять и использовать повторно.

**3. Что такое JSX?**

Синтаксис, который позволяет записывать структуру интерфейса прямо в JavaScript-коде. Он похож на HTML, но на самом деле превращается в вызовы функций React.

**4. Чем JSX отличается от обычного HTML?**

Вместо `class` используется `className`, вместо `for` у подписей `htmlFor`, атрибуты SVG пишутся в camelCase. Все теги должны быть закрыты, у компонента один корневой элемент, а значения из JavaScript вставляются в фигурных скобках.

**5. Для чего используется className?**

Он задаёт CSS-класс элементу. Слово `class` в JavaScript зарезервировано под объявление классов, поэтому в JSX вместо него `className`.

**6. Как создать React-проект с помощью Vite?**

Выполнить `npm create vite@latest my-project` и выбрать React и JavaScript. Затем перейти в папку, установить зависимости командой `npm install` и запустить `npm run dev`.

**7. Для чего используется файл App.jsx?**

В нём лежит главный компонент приложения. Он собирает страницу из остальных компонентов, а `main.jsx` выводит его в элемент `#root`.

**8. Для чего нужна папка components?**

Для собственных компонентов проекта, по одному файлу на компонент. Так `src` не превращается в свалку файлов, и сразу видно, из чего состоит страница.

**9. Как подключить компонент в другой компонент?**

Импортировать его, например `import Header from "./components/Header"`, и использовать как тег: `<Header />`. Компонент должен экспортироваться, в проекте это `export default`.

**10. Почему использование компонентов удобно при разработке больших веб-приложений?**

Большой интерфейс делится на части, над которыми можно работать независимо. Ошибку проще найти, потому что она живёт в одном небольшом файле, а изменение блока не затрагивает остальные.

**11. Что такое повторное использование компонентов?**

Один и тот же компонент подключается в нескольких местах. В работе `ProductCard` выводится шесть раз, `Logo` стоит и в шапке, и в подвале, а различия задаются параметрами.

**12. Чем React-компонент отличается от обычного HTML-блока?**

HTML-блок это статичная разметка, которую приходится копировать, если нужен второй такой же. Компонент это функция: его можно вызвать несколько раз, передать ему данные, а в дальнейшем дать ему собственное состояние и поведение.
