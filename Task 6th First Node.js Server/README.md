# Практическая работа №6. Создание первого сервера на Node.js

Первая работа курса, где код выполняется не в браузере, а на сервере. Нужно было поднять
HTTP-сервер на Node.js, который отвечает на запрос из браузера строкой «Сервер успешно
работает», и вторым заданием переделать ответ так, чтобы он отдавал название колледжа,
фамилию с именем и номер группы.

## Описание решения

```
Solution/
    package.json      описание проекта, создан через npm init -y
    server.js         основное задание, отвечает «Сервер успешно работает»
    server-info.js    дополнительное задание, отдаёт колледж, ФИО и группу
```

Оба задания я оставил отдельными файлами, хотя в методичке второе сформулировано как
«измените сервер». Если переписать `server.js` поверх, основное требование про строку
«Сервер успешно работает» станет нечем показать, а так видно оба варианта. Порт у них
общий, 3000, поэтому одновременно они не запускаются.

Ни одной внешней библиотеки здесь нет: модуль `http` встроен в Node.js, ставить через npm
ничего не нужно. Поэтому в `package.json` нет блока `dependencies`, а папка `node_modules`
не появляется вообще.

## Как запустить

Нужен установленный Node.js, проверить можно командами `node -v` и `npm -v`. Дальше из
папки `Solution`:

```bash
node server.js
```

В терминале появится «Сервер запущен на порту 3000», после чего http://localhost:3000
в браузере покажет ответ. Останавливается сервер сочетанием Ctrl+C, сам он не завершается:
`server.listen()` держит процесс живым, пока слушает порт.

Второй вариант запускается так же, `node server-info.js`. В `package.json` прописаны
короткие команды, `npm start` и `npm run info`, чтобы не набирать имена файлов.

Я проверял оба на Node.js 24.14.0.

## Разбор кода

Весь сервер это три вызова. Сначала подключается встроенный модуль:

```js
const http = require("http");
```

Потом создаётся сам сервер. В `createServer()` передаётся функция, которую Node вызывает на
каждый входящий запрос, отдавая в неё объект запроса и объект ответа:

```js
const server = http.createServer((request, response) => {
    response.writeHead(200, {
        "Content-Type": "text/plain; charset=utf-8"
    });
    response.end("Сервер успешно работает");
});
```

`writeHead(200, ...)` отправляет строку статуса и заголовки: 200 означает, что запрос
обработан успешно. Заголовок `Content-Type` говорит браузеру, что дальше идёт обычный
текст, а не HTML. Часть `charset=utf-8` обязательна, без неё браузер угадывает кодировку
сам и русские буквы превращаются в мусор. `end()` дописывает тело ответа и закрывает
соединение, после него в этот ответ уже ничего не добавить.

Последним шагом сервер занимает порт:

```js
server.listen(3000, () => {
    console.log("Сервер запущен на порту 3000");
});
```

Функция во втором аргументе срабатывает один раз, когда порт успешно занят. Если порт уже
занят другой программой, Node падает с ошибкой `EADDRINUSE`, и тогда нужно либо освободить
порт, либо поменять номер в коде.

В `server-info.js` меняется только тело ответа. Колледж, фамилия и группа вынесены в
константы, а сама строка собрана через шаблонный литерал с переносами `\n`:

```js
response.end(
    `${COLLEGE}\nСтудент: ${STUDENT}\nГруппа: ${GROUP}`
);
```

Переносы работают именно потому, что тип содержимого `text/plain`. Будь там `text/html`,
браузер склеил бы всё в одну строку и понадобился бы тег `<br>`.

Обработчик не смотрит на адрес запроса, поэтому любой путь на этом сервере отдаёт один и
тот же ответ, будь то `/` или `/что-угодно`. Разбор адресов появится в следующей работе,
когда дойдёт до маршрутов.

## Теоретическая часть

**Node.js** это среда выполнения JavaScript вне браузера. Построена на движке V8, том же,
что работает внутри Google Chrome, но вместо DOM и окна браузера даёт доступ к файловой
системе, сети и процессам операционной системы. За счёт этого на JavaScript пишут
серверные приложения, API, чат-боты, микросервисы и утилиты командной строки.

**npm** (Node Package Manager) ставится вместе с Node.js и отвечает за пакеты: установка
библиотек, учёт зависимостей проекта, запуск скриптов, обновление версий. Команда
`npm init -y` создаёт `package.json` со значениями по умолчанию, без вопросов.

**package.json** хранит паспорт проекта: имя, версию, описание, точку входа, список
зависимостей и короткие команды в разделе `scripts`. По нему `npm install` на другой машине
восстанавливает окружение, поэтому сам файл в репозиторий кладут, а `node_modules` нет.

**Сервер** это программа, которая ждёт запросы клиентов и отвечает на них. Схема обмена
простая: браузер отправляет HTTP-запрос, сервер его обрабатывает и возвращает HTTP-ответ,
браузер показывает результат.

**Порт** это номер от 0 до 65535, по которому операционная система понимает, какой именно
программе отдать пришедшее соединение. Один компьютер держит много серверов сразу, лишь бы
номера не совпадали. За HTTP закреплён 80, за HTTPS 443, а 3000 просто прижился в учебных
и рабочих проектах на Node.js, потому что он свободен и не требует прав администратора.
Локальный сервер открывается по адресу http://localhost:3000.

Отдельная бытовая деталь из методички: на многих машинах после установки Node.js команды
`node` и `npm` не находятся, пока путь к нему не пропишут в системную переменную `PATH` и
не перезапустят терминал или редактор.

## Ответы на вопросы

**1. Что такое Node.js?**

Среда выполнения JavaScript вне браузера, построенная на движке V8. Позволяет запускать
JS-код на сервере и писать на нём веб-серверы, API, утилиты и приложения реального времени.

**2. Для чего используется npm?**

Это менеджер пакетов для Node.js. Через него ставят библиотеки, управляют зависимостями
проекта, обновляют версии пакетов и запускают прописанные в `package.json` скрипты.

**3. Что хранится в файле package.json?**

Сведения о проекте: название, версия, описание, главный файл, лицензия, список
зависимостей и команды запуска в разделе `scripts`.

**4. Что такое сервер?**

Программа, которая принимает запросы от клиентов и отправляет им ответы. В этой работе
клиентом выступает браузер, а сервером процесс Node.js, слушающий порт 3000.

**5. Что такое HTTP-запрос?**

Сообщение, которое клиент отправляет серверу по протоколу HTTP. В нём указан метод (GET,
POST и другие), адрес запрашиваемого ресурса, заголовки и при необходимости тело с
данными.

**6. Что такое HTTP-ответ?**

Сообщение, которым сервер отвечает на запрос. Состоит из кода состояния (200 успешно,
404 не найдено, 500 ошибка сервера), заголовков вроде `Content-Type` и тела с самим
содержимым.

**7. Для чего используется порт?**

Порт определяет, какому приложению достанется входящее сетевое соединение. Благодаря
номерам на одном компьютере одновременно работают несколько серверов, не мешая друг другу.

**8. Какой командой запускается Node.js-приложение?**

`node имя_файла.js`, в этой работе `node server.js`. Если в `package.json` прописан скрипт,
можно короче: `npm start`.

**9. Как открыть локальный сервер в браузере?**

Ввести в адресной строке `http://localhost:` и номер порта, на котором запущен сервер.
Здесь это http://localhost:3000. Вместо `localhost` работает и `127.0.0.1`.

**10. Что делает метод createServer()?**

Создаёт объект HTTP-сервера и привязывает к нему функцию-обработчик, которая вызывается на
каждый входящий запрос и получает объект запроса и объект ответа. Сам по себе
`createServer()` соединения ещё не принимает, для этого у созданного сервера вызывается
`listen()` с номером порта.
