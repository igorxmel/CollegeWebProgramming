# ПР №13. Передача данных между компонентами. Props, динамические списки и обработка массивов

## Как запустить

Перейти в папку решения:

```
cd Solution
```

Установить зависимости:

```
npm install
```

Запустить сервер разработки:

```
npm run dev
```

Vite напишет адрес, обычно это `http://localhost:5173`. Результаты обработки массива выводятся в консоль браузера, она открывается через F12. Production-сборка:

```
npm run build
```

## На чём основана работа

Методичка прямо запрещает отдельное демонстрационное приложение, поэтому работа продолжает лендинг из [ПР №12](../Task%2012th%20React%20Migration), который сам вырос из [ПР №1](../Task%201st%20Responsive%20Layout%20with%20HTML5%20and%20CSS3). Повторяющийся элемент это карточка кроссовок из каталога, в ПР №12 все шесть карточек были одинаковыми, теперь у каждой свои данные.

## Данные

В `data.js` лежит массив `items` из шести объектов. Названия, описания, цены и картинки взяты из каталога лендинга, то есть из ПР №1.

```js
{
    id: 1,
    title: "Urban Classic",
    description: "Низкий силуэт из плотного текстиля. ...",
    category: "Повседневные",
    image: "/images/product-1.svg",
    isActive: true,
    price: 6490
}
```

Обязательные поля `id`, `title`, `description`, `category`, `image`, `isActive` на месте, дополнительное свойство это `price`: оно же числовое, по нему идёт сортировка. Цена в лендинге была строкой с пробелом, здесь это число, а пробел между тысячами добавляет `toLocaleString("ru-RU")`.

Два значения в данных мои, в лендинге их не было: категории и признак наличия. Категорий три, `Беговые`, `Повседневные`, `Баскетбольные`, как в каталоге из базы проекта. Одна модель, Desert Walk, помечена как отсутствующая (`isActive: false`), иначе непонятно было бы, как выглядит неактуальный элемент.

## Компоненты

`ProductCard` получает данные через props и сразу деструктурирует их в параметрах функции. Условный рендеринг сделан тернарным оператором: статус «В наличии» или «Нет в наличии», у отсутствующей модели ещё и добавляется класс `product-card--inactive`, а кнопка получает `disabled`.

```jsx
function ProductCard({ title, description, category, image, isActive, price }) {
```

`ProductList` принимает массив и ничего не знает о конкретных карточках. Они строятся из массива, вручную в нём не прописано ни одной.

```jsx
{items.map(item => (
    <ProductCard key={item.id} {...item} />
))}
```

`{...item}` разворачивает объект в набор props, поэтому поля объекта и параметры карточки должны называться одинаково. В качестве `key` стоит `id`, а не индекс: если список начнут сортировать или фильтровать, React не перепутает карточки.

`ItemStats` получает тот же массив и считает три числа: сколько всего моделей, сколько в наличии и сколько категорий. Категории считаются через `Set`, который хранит только уникальные значения.

```jsx
const categories = new Set(items.map(item => item.category));
```

Блок стоит в `ProductList` над сеткой карточек.

## Обработка массива

В `App.jsx` перед выводом страницы массив обрабатывается, а результат уходит в консоль, как разрешает методичка.

```jsx
const activeItems = items.filter(item => item.isActive);
const sortedItems = [...items].sort((a, b) => a.price - b.price);
```

`filter()` собирает новый массив из моделей в наличии. Сортировка идёт по цене от дешёвых к дорогим, и перед ней массив копируется через `[...items]`, потому что `sort()` меняет массив на месте, а `items` нужен в исходном порядке для вывода. Количество берётся из `length`: всего шесть, в наличии пять.

В режиме разработки сообщения в консоли дублируются. Это `StrictMode` из `main.jsx`, он намеренно рендерит компоненты дважды, в собранной версии вывод будет один.

## Оформление

Стили остались прежними, цвета и шрифты Dream Sneakers, добавлено только нужное для этой работы: плашка категории поверх картинки, строка статуса, блок статистики на розовом фоне и приглушённый вид отсутствующей модели. Сетка и сама карточка не менялись.

## Теоретическая часть

Интерфейс делится на компоненты: небольшие независимые части, каждая отвечает за свой кусок страницы. Их можно использовать повторно, менять по отдельности и собирать в приложение.

Данные от родителя к ребёнку идут через props. Родитель записывает их как атрибуты, ребёнок получает объект `props` или сразу деструктурирует его в параметрах. Передать можно не только строки, но и числа, булевы значения, массивы и объекты, всё, кроме строк, в фигурных скобках.

Список строится из массива объектов методом `map()`, каждому элементу нужен уникальный `key`. Перед выводом массив можно обработать: `filter()` оставляет подходящие элементы, `sort()` упорядочивает, `length` даёт количество. В Vue то же делают `v-for`, `v-if` и `computed`, но здесь по методичке выбран React.

## Ответы на вопросы

1. **Что такое компонент в современной веб-разработке?** Отдельная часть интерфейса со своей разметкой и логикой, например карточка товара, шапка или форма. В React это функция, которая возвращает JSX.

2. **Для чего используется компонентный подход?** Чтобы не дублировать код, делить приложение на понятные части и менять одну часть, не трогая остальные. Один компонент можно использовать много раз.

3. **Что такое Props?** Свойства компонента, через которые родитель передаёт ему данные. Внутри компонента они только читаются.

4. **Как осуществляется передача данных от родительского компонента к дочернему?** Родитель пишет данные как атрибуты при вызове дочернего компонента, например `<ProductCard title="Urban Classic" price={6490} />`, а дочерний получает их в параметре.

5. **Что такое деструктуризация?** Извлечение значений из объекта или массива в отдельные переменные. В компонентах её пишут прямо в параметрах: `function ProductCard({ title, price })` вместо `props.title` и `props.price`.

6. **Какие типы данных можно передавать через Props?** Любые: строки, числа, булевы значения, массивы, объекты и даже функции. Всё, кроме строкового литерала, пишется в фигурных скобках.

7. **Для чего используется метод `map()`?** Он перебирает массив и возвращает новый массив из результатов. В React с его помощью массив объектов превращается в массив компонентов, и они выводятся на страницу.

8. **Как во Vue реализуется динамический вывод списка?** Директивой `v-for`: `<InfoCard v-for="item in items" :key="item.id" ... />`.

9. **Для чего необходимо указывать уникальный `key`?** По нему React отличает элементы списка друг от друга и при изменении данных обновляет только то, что изменилось, а не пересоздаёт всё. Лучше брать `id`, а не индекс.

10. **Чем отличаются методы `map()` и `filter()`?** `map()` возвращает массив той же длины, в котором каждый элемент преобразован. `filter()` возвращает только те элементы, для которых условие истинно, поэтому массив может стать короче.

11. **Для чего используется метод `sort()`?** Для упорядочивания элементов массива. Правило задаёт функция сравнения, например `(a, b) => a.price - b.price` для сортировки по возрастанию цены.

12. **Почему при сортировке массива рекомендуется создавать его копию?** `sort()` меняет исходный массив, а не возвращает новый. Если отсортировать `items` напрямую, изменится порядок и там, где он нужен прежним. Копия делается через `[...items]`.

13. **Для чего используется структура данных `Set`?** Для хранения только уникальных значений. Если положить в неё все категории, повторы пропадут, и `size` покажет количество разных категорий.

14. **Что такое условный рендеринг?** Вывод разных элементов в зависимости от данных: `{isActive && <span>...</span>}` или тернарный оператор. Во Vue для этого `v-if` и `v-else`.

15. **Какие преимущества даёт создание универсальных компонентов?** Один компонент выводит любой элемент массива, поэтому новая модель в каталоге это новый объект в `data.js`, а не новая разметка. Выше единообразие и меньше кода.
