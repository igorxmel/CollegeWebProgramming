# ПР №14. Управление состоянием компонентов. События и интерактивность интерфейса

Каталог Dream Sneakers из тринадцатой работы стал интерактивным: категории переключаются кнопками, названия ищутся по строке, у каждой карточки есть кнопка избранного и раскрывающееся описание, а статистика пересчитывается вслед за тем, что видит пользователь. Остальные секции страницы остались как были.

Методичка просит дополнить карточку и статистику из предыдущей практической, поэтому работа продолжает [ПР №13](../Task%2013th%20Props%20and%20Dynamic%20Lists). Там же уже был массив данных, `ProductCard` и `ItemStats`. Из трёх фреймворков, которые допускает методичка, выбран React, как и в двух предыдущих работах.

Вывод в консоль из ПР №13 (`filter()` и `sort()` в `App.jsx`) убран: он был нужен для той работы, а здесь результат фильтрации виден прямо на странице.

## Данные

К каждой модели в `data.js` добавлено поле `details`: два предложения для блока «Подробнее». Тексты мои, в лендинге их не было. Они повторяют смысл описания (беговая модель подходит для пробежек, замшевая для межсезонья) и не называют конкретных характеристик вроде размеров или материалов. Категории те же три: `Беговые`, `Повседневные`, `Баскетбольные`.

## Задание 1. Избранное

`FavoriteButton` хранит одно значение, `isFavorite`, и переключает его по клику. От него зависят текст кнопки («В избранное» и «В избранном») и класс `favorite--active`, который закрашивает кнопку акцентным цветом.

```jsx
const [isFavorite, setIsFavorite] = useState(false);

<button
    className={isFavorite ? "favorite favorite--active" : "favorite"}
    onClick={() => setIsFavorite(!isFavorite)}
>
    {isFavorite ? "В избранном" : "В избранное"}
</button>
```

Компонент стоит внутри `ProductCard`. Директива `'use client'` не нужна, это обычный React, а не Next.js. Состояние не меняется напрямую: только через `setIsFavorite`.

## Задание 2. Категории

В `ProductList` лежат два состояния: `selectedCategory` (начальное значение «Все») и `search`. Список категорий не записан руками, он собирается из данных:

```jsx
const categories = ["Все", ...new Set(items.map(item => item.category))];
```

`Set` убирает повторы, «Все» стоит первым и возвращает полный список. Кнопки строит `map()` с `key={category}`, выбранная получает класс `filters__button--active`. Нужные карточки отбирает `filter()`:

```jsx
const categoryItems = items.filter(item =>
    selectedCategory === "Все" || item.category === selectedCategory
);
```

Исходный массив `items` не меняется, фильтр каждый раз строит новый.

## Задание 3. Поиск

Поле ввода управляемое: его значение лежит в состоянии `search`, а `onChange` обновляет его при каждой букве. Поиск идёт по результату фильтрации по категории, а не по всему массиву, поэтому два условия работают вместе:

```jsx
const filteredItems = categoryItems.filter(item =>
    item.title.toLowerCase().includes(search.trim().toLowerCase())
);
```

Регистр отбрасывается с обеих сторон, пробелы по краям запроса обрезаются через `trim()`. Если `filteredItems` пуст, вместо сетки выводится сообщение «По вашему запросу ничего не найдено.»

## Задание 4. Подробнее

В `ProductCard` своё состояние `isOpen`. Оно в карточке, а не в списке, поэтому каждая карточка раскрывается независимо от остальных. Текст кнопки меняется («Подробнее» и «Свернуть»), блок с `details` выводится условным рендерингом:

```jsx
{isOpen && <p className="product-card__details">{details}</p>}
```

## Задание 5. Статистика

`ItemStats` ничего не считает сам, ему приходят четыре готовых числа через props:

| Показатель | Откуда берётся |
| --- | --- |
| Всего моделей | `items.length` |
| В выбранной категории | `categoryItems.length` |
| Найдено | `filteredItems.length` |
| Из них в наличии | `filteredItems.filter(item => item.isActive).length` |

Все вычисления сделаны один раз в `ProductList`, там же, где лежат состояния. Любое изменение категории или запроса перерисовывает список, и числа обновляются вместе с карточками.

## Задание 6. Оформление

Стили добавлены в тех же цветах и шрифтах, что и остальная страница: выбранная категория закрашена акцентом `#ec1c5f`, поле поиска получает акцентную рамку в фокусе, кнопка избранного в нажатом состоянии залита акцентом, а в ненажатом обведена им, блок «Подробнее» стоит на розовом фоне, сообщение об отсутствии результатов выровнено по центру. Избранное обозначено самой кнопкой, у карточки отдельной подсветки нет.

## Грабли

Состояние карточки живёт ровно столько, сколько живёт сама карточка. Когда фильтр убирает её из списка, React её удаляет, а при возвращении создаёт заново с начальным состоянием. Поэтому если добавить модель в избранное, переключиться на другую категорию и вернуться, кнопка снова скажет «В избранное», а раскрытое описание свернётся. Я проверил это в браузере. Если нужно, чтобы избранное переживало фильтрацию, состояние придётся поднять в `ProductList` и передавать в кнопку через props. Здесь оно оставлено в самом `FavoriteButton`, как просит первое задание.

## Теоретическая часть

Состояние это данные компонента, которые меняются во время работы приложения. Когда состояние меняется, React заново рисует ту часть интерфейса, которая от него зависит. Props приходят снаружи и компонент их только читает, state компонент меняет сам.

В React состояние создаёт хук `useState()`: он возвращает текущее значение и функцию для его изменения. Менять значение напрямую нельзя, только через эту функцию, иначе React не узнает, что надо перерисовать. Во Vue 3 для этого `ref()`, а вычисляемые значения, как отфильтрованный список, дают `computed()`.

События вешаются на элементы атрибутами: `onClick` для кликов и `onChange` для ввода. Отфильтрованный список не хранится как отдельное состояние, он каждый раз вычисляется из исходного массива и текущих значений категории и запроса. Так данные не расходятся.

## Ответы на вопросы

1. **Что такое состояние компонента?** Данные, которые принадлежат компоненту и меняются во время работы: выбранная категория, текст в поиске, открыто описание или нет. При изменении состояния обновляется связанная с ним часть интерфейса.

2. **Чем Props отличаются от State?** Props компонент получает от родителя и не может менять. State принадлежит самому компоненту и меняется от действий пользователя. Например, `ProductCard` получает `title` через props, а `isOpen` хранит сам.

3. **Для чего используется хук `useState()`?** Чтобы создать в функциональном компоненте состояние. `const [count, setCount] = useState(0)` даёт текущее значение `count` и функцию `setCount`, которая меняет его и просит React перерисовать компонент.

4. **Что такое реактивность во Vue?** Механизм, при котором Vue следит за изменением данных и сам обновляет связанные с ними элементы шаблона. Писать код обновления страницы не нужно.

5. **Для чего используется функция `ref()`?** Для создания реактивного значения в Composition API: `const count = ref(0)`. В скрипте значение читается и меняется через `count.value`, а в шаблоне пишется просто `count`.

6. **Чем отличается управление состоянием в React и Vue 3?** В React состояние меняется только через функцию из `useState`, а компонент при этом выполняется заново. Во Vue значение из `ref()` можно присваивать напрямую (`count.value++`), Vue отслеживает изменения сам, а производные данные считает `computed()`.

7. **Для чего в Next.js используется директива `'use client'`?** Она в первой строке файла помечает компонент как клиентский. В App Router компоненты по умолчанию серверные и не могут использовать `useState` и обработчики событий, для интерактивных нужна эта директива. В обычном React она не нужна, поэтому здесь её нет.

8. **Что такое обработчик события?** Функция, которая вызывается, когда с элементом что-то произошло: клик, ввод, отправка формы. В React её передают в атрибут, например `onClick={() => setIsOpen(!isOpen)}`.

9. **Для чего используются `onClick` и `onChange` в React?** `onClick` срабатывает при клике на элемент, в работе так переключаются категории, избранное и описание. `onChange` срабатывает при изменении значения поля ввода, здесь он записывает текст из поиска в состояние через `event.target.value`.

10. **Что такое директива `v-model` во Vue?** Двусторонняя привязка поля ввода к данным. Введённый текст попадает в переменную, а изменение переменной обновляет поле. В React то же делается руками: `value` и `onChange` вместе.

11. **Что такое условный рендеринг?** Вывод разных элементов в зависимости от состояния. В работе так показывается описание только при `isOpen` и сообщение «ничего не найдено» только при пустом списке. В React это `&&` или тернарный оператор, во Vue `v-if` и `v-else`.

12. **Как реализовать фильтрацию массива на основе состояния?** Исходный массив хранить отдельно, выбранное значение держать в состоянии, а результат получать методом `filter()`: `items.filter(item => selectedCategory === "Все" || item.category === selectedCategory)`. При смене состояния список вычисляется заново.

13. **Для чего используется `computed()` во Vue?** Для вычисляемого свойства, которое зависит от других реактивных данных и пересчитывается само, когда они меняются. Подходит для отфильтрованного списка: он зависит от категории и поиска. В React то же делается обычным выражением в теле компонента.

14. **Почему не рекомендуется изменять исходные данные напрямую?** React сравнивает старое и новое значение, чтобы понять, нужна ли перерисовка, и прямое присваивание этого не вызывает. Кроме того, изменённый исходный массив пропадёт для всех, кто им пользуется: после фильтрации с удалением элементов вернуться к полному списку было бы нельзя.

15. **Какие элементы интерфейса вашего проекта используют состояние?** Кнопки категорий и поле поиска (`selectedCategory` и `search` в `ProductList`), кнопка избранного (`isFavorite` в `FavoriteButton`) и раскрытие описания (`isOpen` в `ProductCard`). Статистика своего состояния не имеет, она считается из состояния списка.
